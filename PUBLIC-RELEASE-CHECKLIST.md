# Public Portfolio Release Checklist

This checklist is retained as a reference for safely documenting a real-world client project publicly.

## Repository

- [ ] Confirm no secrets exist in public files.
- [ ] Confirm no client/customer personal information is included.
- [ ] Confirm no private screenshots are included.
- [ ] Confirm no backup/archive files are included.
- [ ] Confirm no API keys, tokens or credentials are included.
- [ ] Confirm deployment secrets remain in GitHub/Azure secret management.
- [ ] Confirm production source code remains in the private implementation repository.

## Website

- [ ] Confirm the public website contains no test credentials.
- [ ] Confirm form endpoints are safe to expose publicly.
- [ ] Confirm no internal admin links are exposed.
- [ ] Confirm images do not contain confidential information.

## Documentation

- [ ] Keep architecture diagrams at a high level.
- [ ] Describe security controls without publishing secrets.
- [ ] Use sanitized examples for DNS and Microsoft 365 configuration.
- [ ] Avoid publishing mailbox contents or migration data.

## Portfolio

- [ ] Add a clear repository description.
- [ ] Add relevant GitHub topics.
- [ ] Pin the repository to the GitHub profile.
- [ ] Add the project to LinkedIn.
- [ ] Publish a LinkedIn case-study post.
